1. What the camera sees

The bottle squeezes the label towards its edges. The squares stop being square, and the decoder reads nothing at all.

2. The function

Walk around the bottle in equal steps and those steps land unevenly in the photo — spread out at the front, crushed towards the silhouette, following a sine. To undo it, each output column is an equal step around the bottle, and we fetch the pixel from wherever that step actually landed: 

h = 1 - |c|                                    half-width of the visible arc
source(u) = c + h * sin( t * (u - c) / h ) / sin(t)

  u        output position, normalised so the frame spans -1 .. +1
  source   where to read from, same units
  t        how much bottle curve half the frame covers  (radians)
  c        where the bottle's nearest edge sits         (-1 .. +1)

  t -> 0 collapses to source(u) = u, i.e. no change at all.
  Pixel column = (source + 1) / 2 * width, sampled between neighbours.

That is the whole distortion model — sourceCoord() in dewarp.js. The axis parameter only decides whether it is applied across columns (standing bottle) or down rows (lying one). Since the result depends solely on t, c and the frame width, each correction is precomputed once into a lookup table and reused for every row of every frame.

3. Every correction it tries

Each panel is the same photograph re-sampled with the parameters shown. The graph is how far that correction drags each column sideways: the dashed line is "no shift", and the green curve is the shift, scaled to its own peak (given in pixels beside the parameters). Green-bordered panels decoded something — notice that no single panel gets both labels, which is why the scanner pools them.
